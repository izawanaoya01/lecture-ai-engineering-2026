- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 手順5の質問で `requests=2`、`tool_calls=1`。ツールを呼ぶと決めるので1回、ツールの結果を読んで回答を書くので1回。

- 追加したツールと、docstring に書いた説明：

  - docstring：「指定した回（1始まりの整数）の用語から1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。」
  - ツールは問題と答えを両方返すが、手順5の実行ではモデルは問題だけを出し、答えは書かなかった。INSTRUCTIONS の「宿題の答えそのものは書かず」や「確認問題」という言葉からの判断と考えられ、毎回そうなるとは限らない。

## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(title: str, content: str) -> str` を作った。`learning_log/` に Markdown で保存する。
    - ファイル名はモデルの引数から作らず、日時（`%Y%m%d-%H%M%S.md`）にした。`title` に `../` などを入れられて、作業フォルダの外に書き込まれるのを防ぐため（講義 Part 9 の信頼境界）。
  - `app/agent.py` で `requires_approval=True` を付けて登録し、`output_type=[str, DeferredToolRequests]` にした。
  - CLI に `ask_approvals` を足した。承認待ちのツール名と引数（保存される中身）を表示し、`y` なら承認、それ以外なら `ToolDenied("利用者が実行を断りました。")` を返す。
  - `message_history=result.all_messages()` と `deferred_tool_results` を渡して続きを実行する。続きでまた承認待ちになっても対応できるよう、`while` で回す。
- 結果：
  - `--list-tools` でツールが4個になり、`uv run pytest -q` は 11 passed。
  - 承認した場合（「今日学んだ make_quiz の作り方を学習ログに記録して」→ `y`）：`[承認待ち] save_learning_log(...)` で止まり、`y` の後に `learning_log/20261106-124520.md` が作られた。
  - 断った場合（「LoRAについて学んだことを学習ログに記録して」→ `n`）：
    ```
    [tool call]   search_glossary({'query': 'LoRA'})
    [tool call]   save_learning_log({'title': 'LoRAの学習ログ', 'content': '# 学習ログ：LoRAについて ...'})
    [tool return] save_learning_log -> 利用者が実行を断りました。
    ```
    ファイルは作られなかった。モデルは勝手に保存し直さず、保存内容のプレビューを示して「よければ保存を指示してください」と返した。
- 気づき・疑問：
  - make_quiz の記録は「make_quiz の実装方法や使い方についての学習内容を記録しました」の1文だけで、中身が薄かった。エージェントは毎回新しい会話として始まり（ステートレス）、`make_quiz` は用語集にも無いので、モデルには書く材料が質問文しかなかった。LoRA では `search_glossary` で定義を取れたので、中身が具体的になった。ツールの出来より、モデルに何を渡すかで結果が決まると感じた。
  - make_quiz の記録を保存した後の回答は、最後が「（関連：第N回）」になっていた。INSTRUCTIONS の「関係する回（第N回）を示す」の「第N回」が、そのまま出ている。このときは `search_glossary` を呼んでおらず、書くべき回の番号が分からなかったためと考えられる。指示の中の例や書式が、材料が無いときにはそのまま出てしまうことがある。
  - 保存した Markdown で見出しが2つ重なった。関数が `# {title}` を付けたうえに、モデルも `content` の先頭に見出しを書いたため。docstring に「見出しは付けない」と書けば防げると思う。
  - 承認をはさむと実行が2回に分かれ、`--trace` の `[usage]` は最後の実行の分（`requests=1`）しか出ない。費用やレート制限を見積もるときは、合計を数える必要がある。
  - 承認画面にツールの引数がそのまま出るので、何が保存されるかを読んでから判断できた。講義の Claude Code の承認画面と同じ考え方だと分かった。一方で、毎回中身を読むのは手間で、講義で触れた「承認が形だけになる」問題も実感できた。
  - 疑問：同じ秒に2回保存すると上書きされる。取り消しにくい操作なので、既存ファイルがあれば別名にするなどの対策が要るか。
